状态：首批已实现，默认关闭。入口为 General → Vim features → Live Preview conceal；展开策略支持停留后显示和仅编辑时显示。延迟以毫秒设置，默认 200，范围 0–10000，0 表示立即显示。实现与限制见 [[preview-conceal]]；列表、Callout、代码块和对象仍属后续阶段。

## 目标

在 Obsidian Live Preview 中，normal 和 characterwise visual 模式可以沿显示出来的正文移动，不因经过粗体、链接等格式而立即展开 Markdown 源码。保留现有 Vim fork、映射、操作符、文本对象、撤销和点重复机制。实现归属 Motions，不要求修改 LaTeX Suite 或发布新的 Vim fork。

展开策略与移动单位分开：可以提供停止导航后延迟展开，以及进入编辑模式才展开两种策略。是否默认采用 200ms、visual 是否延迟展开，实施前以实际行为验证后确定；现有行为保持为默认，功能显式开启。

已展开的源码区域应保持展开，区域内移动不重新切回预览；只有光标离开才恢复隐藏。相邻模块分别拥有展开状态，即使隐藏标记在源码上相接也不能合并为同一区域。渲染和导航必须共用该状态，使展开后的分隔符、地址和别名目标可以直接访问。

## 已有基础与实现边界

`src/vim/atomic-range-motions.ts` 已让部分导航尊重 CM6 `EditorView.atomicRanges`，解决进入已有隐藏区间的问题。它不能阻止 Obsidian 因光标进入正文而主动显示语法，也不提供预览文字与源码之间的完整映射。

新功能还需要受控的显示层和位置映射。可以复用 Markdown 语法树、CM6 decorations 与现有图片和表格适配，但不能假设所有核心 widget 都支持统一冻结。首先在真实 Obsidian 上验证普通格式的隐藏策略，避免全局原型修改、伪造光标位置或在已展开后反复把光标拉回。

## 导航单位

正文的一个移动单位是一个用户感知的字符，即字素簇；不按 UTF-16 长度、固定像素宽度或源码标记长度计数。隐藏的语法不占导航步数，不能映射到宿主源码的内容作为对象或独立导航上下文处理。

| 格式                                       | 建议导航单位                                             | 实施范围   |
| ------------------------------------------ | -------------------------------------------------------- | ---------- |
| 普通文字、标点、正文空格、组合字符和 emoji | 一个可见字素簇                                           | 基础       |
| 粗体、斜体、删除线、高亮、嵌套格式         | 正文逐字，分隔符不计步                                   | 首批       |
| 行内代码                                   | 正文逐字，外围反引号不计步                               | 首批       |
| 标题                                       | 标题文字逐字，标题前缀不计步                             | 首批       |
| Markdown 链接                              | 显示文字逐字，地址和语法标记不计步                       | 首批       |
| Wikilink 与别名                            | 按实际显示名称逐字，保存到源码的映射                     | 首批       |
| 标签和直接显示的网址                       | 按可见文字逐字，可见的 `#`、`/` 等计步                   | 后续       |
| 列表、引用                                 | 正文逐字，项目符号、序号、引用前缀作为结构               | 后续       |
| 任务列表                                   | 复选框作为对象，正文逐字，勾选采用独立动作               | 后续       |
| Callout                                    | 自定义标题和正文逐字，图标和边框不计步；生成标题作为控件 | 后续       |
| 普通代码块                                 | 代码正文逐字，围栏和语言声明不计步                       | 后续       |
| 脚注                                       | 引用标记作为对象，正文逐字                               | 后续       |
| 分割线、图片                               | 整体对象；图片优先复用现有选择能力                       | 后续       |
| 表格                                       | 单元格内部逐字，跨单元格采用结构导航                     | 专门适配   |
| 嵌入笔记、PDF、音视频                      | 宿主笔记内作为整体对象，进入内部后切换导航上下文         | 不纳入首批 |
| Mermaid、Dataview 与其他生成内容           | 默认整体对象，不把输出文字假定为源码字符                 | 不纳入首批 |
| 隐藏注释与隐藏块标识                       | 不产生停靠点，通过明确编辑动作访问源码                   | 后续       |
| Properties                                 | 按字段和控件导航，编辑字段时逐字                         | 保留原机制 |

例如 `**中文**` 只提供“中”“文”两个文字单位，`[说明](https://example.com)` 只提供“说”“明”两个文字单位。嵌入笔记显示的正文不能映射为宿主 `![[笔记]]` 那一行的字符。

## Vim 语义与编辑边界

- 保留 `j/k` 的文档行语义和 `gj/gk` 的显示行语义；表格等结构单独处理。
- `h/l` 和计数使用可见单位，`w/b/e` 的可见文本边界需要单独验证。
- visual 光标、屏幕选区与 Vim 内部 anchor/head 必须一致。源码选区仍然是连续范围，跨格式复制可能包含 Markdown 标记。
- 编辑和文本对象操作先将显示位置准确映射回源码，继续调用原引擎。不能用可见字符数直接替代操作符的源码范围。
- 明确处理源码展开后的位置恢复、IME、鼠标、搜索和跳转；遇到不支持的格式保留现有编辑行为。
- Source mode、内置 Vim 和外部 Neovim 后端不自动纳入此功能。

## 实施阶段

1. 在真实 Obsidian 上测量格式标记的隐藏、显示与 selection 更新时序，验证同一位置在预览和源码之间的映射。
2. 建立首批格式的位置模型，支持嵌套语法、转义、组合字符和按方向跨越隐藏标记。
3. 以显式选项接入 normal 导航，再接入 characterwise visual；建立展开、编辑和恢复流程。
4. 逐类接入列表、Callout、代码块和对象。表格和动态嵌入分别设计适配器。

## 验收

- 快速连续移动不会出现源码闪现或显示与源码之间来回跳动。
- 计数、双向移动、折行和文件末尾位置正确。
- visual 选区、删除、修改、复制、文本对象、撤销和点重复没有范围偏移。
- 新增测试先证明旧行为失败，并针对映射、展开时序和清理做负向对照。
- 在真实 Obsidian 上验证核心格式、主题字体、移动端兼容和大文档响应；单元测试不能代替渲染验证。
