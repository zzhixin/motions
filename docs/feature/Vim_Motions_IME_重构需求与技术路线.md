# 按编辑区域记忆输入法：需求与技术路线

> [!info] 文档定位
> 本文整理 IME 重构的需求与设计约束。当前代码已包含统一的 `InputMethodManager`；验收清单用于逐项核对，不表示这些场景尚未实现或已经全部通过。实际设置见 [[settings#Input method|Input method 设置]]。

## 1. 目标与适用范围

在 Vim Motions 内统一管理不同编辑区域的输入法状态，兼容现有 Normal / Insert 自动切换。笔记、侧边栏输入框和查找框分别记忆状态，不依赖独立输入法插件或 Lua 的 `LeafEnter` / `LeafLeave` 补丁。

| 项目           | 要求                                                                        |
| -------------- | --------------------------------------------------------------------------- |
| 首期环境       | Windows 11、Obsidian、Vim Motions 自带的 CodeMirror Vim 引擎（bundled Vim） |
| 输入法状态     | 中文输入法与英文键盘布局之间的切换；不处理中文输入法内部的中英文模式        |
| 手动切换       | 使用系统配置的输入法快捷键；当前测试电脑使用 `Alt+Shift`                    |
| 查询命令       | `C:\Portable\im-select.exe`                                                 |
| 切换命令       | `C:\Portable\im-select.exe {im}`                                            |
| 程序路径       | 在插件设置中配置绝对路径，不硬编码测试电脑路径                              |
| Normal 目标 IM | 默认 `1033`，沿用现有设置                                                   |
| 首期范围之外   | 其他平台及 Neovim RPC 模式保持原行为，或明确标注适用边界                    |

不轮询输入法，不监听系统输入法切换快捷键，也不要求焦点停留期间实时更新缓存。需要保存时读取实际 IM，离开后的缓存保持冻结；恢复目标区域时使用该区域的缓存或默认策略。

## 2. 编辑区域与状态身份

下表适用于 Obsidian 内部的区域切换；跨应用返回另见第 4 节。

| 区域                         | 状态键                                 | 离开时                                                  | 进入时                                                     |
| ---------------------------- | -------------------------------------- | ------------------------------------------------------- | ---------------------------------------------------------- |
| Markdown 笔记                | Vault + 笔记文件路径                   | 仅在 Insert 模式读取并保存 Insert IM；Normal 不覆盖缓存 | Normal 使用配置的 Normal IM；Insert 恢复该笔记的 Insert IM |
| 插件侧边栏输入框，如 Copilot | 插件或视图类型 + 面板实例 + 输入框用途 | 读取并保存实际 IM                                       | 恢复该输入框的 IM                                          |
| 当前笔记查找框、全局搜索等   | 可可靠识别的稳定逻辑身份               | 读取并保存实际 IM                                       | 有缓存则恢复；无缓存则使用查找框默认 IM                    |

状态身份必须满足以下约束：

- 笔记按文件保存，而非仅按 CodeMirror 视图实例保存；关闭后重新打开仍能恢复 Insert IM。
- 同一笔记多分栏共享文件身份，同时依据当前获得焦点的编辑器判断真实 Vim 模式。
- 普通输入框使用逻辑身份，不能只依赖会被重建的 DOM 元素引用。
- 查找框若反复销毁且无法稳定识别，每次出现均使用查找框默认 IM，不承诺持久化。
- 未知输入框允许降级处理，不把不可靠的 DOM 标识当作稳定身份。
- 文件重命名与删除需要同步维护状态键；其他 Windows 应用不属于插件管理的持久化区域。

### 初始化

非查找框首次获得焦点且没有历史记录时，查询实际 IM 建立初始值，不强制切换。

笔记首次进入 Normal 时仍使用 Normal 目标 IM，但不能据此初始化或覆盖该笔记的 Insert IM。查找框首次使用可配置的默认 IM，默认值为 `1033`。

## 3. Vim 模式与区域交接规则

| 事件                           | 必须执行的顺序与行为                                                        |
| ------------------------------ | --------------------------------------------------------------------------- |
| 笔记 Insert → Normal           | 先保存实际 Insert IM，再切换到 Normal 目标 IM                               |
| 笔记 Normal → Insert           | 恢复该笔记保存的 Insert IM，不能把当前 Normal 的英文写入 Insert 缓存        |
| 焦点 A → B                     | 完成 A 的必要快照，再恢复 B；A 的过期操作不能反过来覆盖 B                   |
| 笔记 → Copilot / 查找框 → 笔记 | 输入框记忆自身 IM；返回笔记时查询该编辑器当前真实 Vim 模式                  |
| 用户手动切换 IM                | 无需即时监听；下一次离开区域或退出 Insert 时，必须保存实际布局              |
| IME composition 进行中         | 不强制切换；组合结束后重新检查区域与模式，再处理仍然有效的待执行操作        |
| 同一编辑器替换笔记             | 即使 DOM 焦点没有变化，也要重新识别文件与真实模式，立即应用新笔记的进入策略 |

## 4. 跨应用切换策略

Obsidian 窗口失焦时，保存当前区域所需的状态。窗口重新获得焦点后，重新识别实际获得 DOM 焦点的区域及其真实 Vim 模式，不能假定仍是离开前的区域。

现有设置 **System remembers IM state across apps**（`imCrossAppStateMemory`，默认开启）区分两种返回策略：

| 返回场景         | 开关开启                                  | 开关关闭                            |
| ---------------- | ----------------------------------------- | ----------------------------------- |
| 返回同一稳定区域 | 沿用系统管理的 IM，不额外查询或切换       | 主动恢复该区域按当前模式应使用的 IM |
| 返回不同区域     | 按新区域的缓存、默认值及真实 Vim 模式恢复 | 同左                                |

开启时的“同一区域返回”是第 2 节进入恢复规则的例外。后续实际发生的 Insert / Normal 模式切换仍按第 3 节处理。

> [!info] 原稿中的两种表述
> 原稿正文要求“返回同一区域时沿用系统状态”，跨应用验收项则要求“恢复区域缓存”。现有开关已经区分两者，因此验收时必须分别写明开启和关闭条件，不能把它们作为同一配置下的两个要求。

## 5. 技术路线与架构边界

### 5.1 复用现有模块，保持唯一所有者

先审查现有实现与事件绑定，再决定需要调整的范围：

| 文件                             | 职责或审查重点                                                     |
| -------------------------------- | ------------------------------------------------------------------ |
| `src/im/input-method-manager.ts` | 统一拥有区域状态、当前焦点、模式交接、查询与切换队列、过期操作校验 |
| `src/im/im-switcher.ts`          | 保留原 `ImSwitcher` 名称的兼容入口                                 |
| `src/im/im-process.ts`           | 外部进程查询与切换、参数和错误处理                                 |
| `src/im/im-mode-watcher.ts`      | 逐编辑器观察真实 Vim 模式                                          |
| `src/im/composition-tracker.ts`  | 组合输入状态与结束通知                                             |
| `src/im/types.ts`                | 编辑区域、模式等共享类型                                           |
| `src/main.ts`                    | IM 初始化、区域识别、焦点事件与设置接入                            |

模式自动切换、焦点切换、Lua API 与 ex 命令必须共用同一个状态和串行执行所有者。收敛重复写入路径，不建立与原 IM 机制并行竞争的新控制器。

兼容既有设置及 `vim.obsidian.im` API；若状态格式发生变化，提供迁移策略。文件和方法的实际 API 以源码为准。

### 5.2 观察真实焦点与模式事件

- 使用文档级 `focusin` / `focusout`，必要时采用 capture 阶段，识别输入框焦点。
- 使用 CodeMirror `EditorView` 的焦点变化及现有逐编辑器 Vim 模式事件，识别笔记和模式。
- 使用窗口级 `blur` / `focus` 或等价激活事件处理跨应用切换。
- `active-leaf-change`、`LeafEnter`、`LeafLeave` 只能提供工作区上下文，不能替代 DOM 焦点事件。
- 同一叶片或编辑器打开新笔记时，补充文件变化的协调路径；不能要求用户再按一次键才同步输入法。
- 优先识别 Copilot、当前笔记查找框、全局搜索框；输入框分类和稳定 ID 策略需要可维护。
- 状态持久化沿用插件已有存储机制；频繁变更先写内存，合并磁盘写入。

### 5.3 串行化查询与切换，校验异步操作归属

一次区域交接按以下顺序执行：

1. 确定旧区域及旧模式。
2. 必要时读取实际 IM，保存旧区域状态。
3. 确认新区域及其当前真实模式。
4. 校验请求仍属于当前焦点代际，再恢复目标 IM。

为焦点交接分配代际 token；过期恢复请求不能执行。由管理器发起的切换不能被误写为用户手动修改。

如果等待期间发生 composition、焦点或模式变化，恢复前必须重新校验，而不是直接执行原先排队的目标。

### 5.4 优先验证失焦快照的可靠性

`im-select` 通过异步子进程读取系统布局。在 `focusout` 后才真正查询时，可能读到新焦点的状态，而非旧区域离开时的状态。

先用带时间戳的事件与查询日志验证以下时序：旧区域失焦、窗口失焦、新区域获焦、查询启动、查询返回、切换启动与返回。

如果确认存在竞态，评估失焦前的鼠标或键盘导航捕获、提前快照，或只在必要交接点采用同步查询等可靠机制，并测量其输入延迟。不能用固定 `setTimeout` 或轮询掩盖竞态，也不能为了提前快照拦截系统输入法切换快捷键。

### 5.5 设置、调用方式与兼容性

复用以下设置：`IM binary path`、`Obtain IM arguments`、`Switch IM arguments`、`Normal mode IM`、Insert 恢复策略、查找框默认 IM，以及跨应用状态记忆开关。

原稿提出“按编辑区域记忆”可选开关；若需要独立于现有 IM 总开关，应先明确两者边界，避免重复控制同一行为。查找框默认 IM 为 `1033`，可配置。

外部命令继续使用 `execFile`，不经过 shell。启动或查询失败时记录错误，保留编辑能力。其他平台与 Neovim RPC 模式的现有行为不能因 Windows 首期重构而改变。

## 6. 验收清单

以下以可恢复上一输入法的 Insert 策略为前提；固定默认 Insert IM 策略需另行验证。清单中的“中文”和“英文”均指系统布局，不指中文输入法内部模式。

### 6.1 笔记与模式

- [ ] A、B 两篇笔记均处于 Insert，A 使用中文、B 使用英文；反复切换后分别恢复。
- [ ] A 为 Normal、B 为 Insert；在 Obsidian 内部切换后，A 使用 `1033`，B 保持自己的 Insert IM。
- [ ] A Insert 中文 → `<Esc>` → A Normal 英文 → `i`，恢复中文。
- [ ] 在同一编辑器中用 `<C-o>` 打开新笔记，新笔记以 Normal 模式立即切换到 `1033`，不需要额外按键。
- [ ] 同一笔记多分栏、关闭后重开、文件重命名及删除时，状态身份和当前模式判断正确。
- [ ] 关闭并重启 Obsidian 后，持久化状态仍按文件或可靠逻辑身份恢复。

### 6.2 插件输入框与查找框

- [ ] 笔记与 Copilot 输入框往返，双方分别保存 IM；回到笔记时遵守其真实 Normal / Insert 模式。
- [ ] Copilot 不同输入框、当前笔记查找框、全局搜索框的 IM 互不覆盖。
- [ ] 插件界面重渲染后，可靠逻辑身份继续生效；无法稳定识别的动态查找框使用默认策略。
- [ ] 使用系统快捷键（测试电脑为 `Alt+Shift`）手动改变布局，离开再返回后正确恢复。

### 6.3 跨应用

- [ ] 开启跨应用状态记忆：从笔记切到其他 Windows 应用，改变系统布局后返回同一稳定笔记区域，沿用系统 IM，不发生额外查询或切换。
- [ ] 关闭跨应用状态记忆：从 Insert 笔记切到其他 Windows 应用并改变布局，返回后恢复该笔记保存的 Insert IM。
- [ ] 关闭跨应用状态记忆：返回 Normal 笔记时恢复 Normal 目标 IM。
- [ ] 返回不同的笔记、侧边栏输入框、当前笔记查找框或全局搜索框时，无论开关状态如何，均按目标区域的身份和模式恢复。
- [ ] 窗口重新获得焦点时，以实际 DOM 焦点为准，正确处理 `focusout` 先于窗口 `blur` 等事件顺序。

### 6.4 竞态、组合输入与性能

- [ ] 快速鼠标或快捷键切换区域时，旧区域的查询与恢复不会覆盖新区域。
- [ ] 中文 IME 正在组字时切换焦点，不丢字、不错误保存，不被过期异步请求覆盖。
- [ ] 不出现固定间隔查询，没有两套互相竞争的 IM 切换逻辑。
- [ ] 查询、进程启动及必要同步快照的延迟经过测量，正常编辑不被无意义的查询和切换阻塞。
- [ ] 既有设置、`vim.obsidian.im` API、错误处理及插件卸载清理保持兼容。

## 7. 实施顺序

1. 审查现有代码和事件时序，先用诊断日志与测试证明失焦快照可靠。
2. 在现有统一管理器中收敛模式与焦点交接，补齐区域识别、代际校验及 composition 处理。
3. 明确跨应用开关条件，完善文件身份、持久化和迁移。
4. 按第 6 节逐项记录验收结果，再运行项目单元测试、类型检查和生产构建。
