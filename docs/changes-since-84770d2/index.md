## 新增功能

### 1. 按编辑区域记忆输入法

输入法状态由统一的 `InputMethodManager` 管理，笔记按 Vault 与文件路径保存身份，插件输入框和查找框按可识别的逻辑区域保存身份。笔记编辑器重建后，仍可在当前管理器生命周期内恢复该笔记已记住的状态。

- 笔记退出 Insert 时先读取并保存 Insert 输入法，再切换到 Normal 输入法；Normal 状态不覆盖笔记的 Insert 记忆。
- 进入 Insert 时，根据现有配置恢复笔记输入法，或使用固定默认值。
- 普通输入框首次获得焦点时读取实际输入法；尚无记忆的查找框使用默认值 `1033`，可在设置中修改。
- 查询与切换串行执行，焦点与操作代际用于拒绝过期恢复，composition 期间等待组合输入结束。

新增 **System remembers IM state across apps** 设置（`imCrossAppStateMemory`），默认开启：跨应用返回同一稳定区域时沿用系统输入法状态；关闭后主动恢复区域状态。返回不同区域时按目标区域及实际 Vim 模式处理。

主要实现：`src/im/input-method-manager.ts`、`src/im/im-mode-watcher.ts`、`src/im/types.ts`、`src/main.ts`。旧 `ImSwitcher` 入口继续兼容现有调用。

此轮需求以 Windows 使用场景为主，区域身份识别仍受第三方输入框结构影响。需求文档中的验收清单不等于所有条目均已通过。详见 [[feature/Vim_Motions_IME_重构需求与技术路线|IME 需求与技术路线]]、[[settings#Input method|输入法设置]]。

### 2. Flash 中文拼音首字母匹配

- Flash 的 `f` / `F` / `t` / `T` 支持拉丁目标字母匹配汉字拼音首字母，例如 `fa` 可找到 `啊`、`安`，同时保留字面匹配。
- Flash `/`、`?` 支持最多四个字符的汉字、英文字母及其混合模式，例如 `/aj` 匹配 `安静`、`氨基`，`/dg` 匹配 `大g`。
- 超出上述模式范围的搜索继续使用原有 Vim 搜索，普通非 Flash 字符查找保持字面行为。

首字母映射预先建立，扫描时复用；匹配位置保留 CodeMirror 的 UTF-16 坐标，避免补充平面字符导致后续标签位置偏移。

主要实现：`src/flash/character-match.ts`、`src/flash/pinyin-initials.ts`、`src/flash/char-mode.ts`、`src/flash/search-mode.ts`。详见 [[flash|Flash 功能说明]]。

### 3. 中文分词 motions 与 text objects

自带 Vim 引擎自动启用中文词边界，覆盖本轮要求的 `w`、`W`、`dw`、`cw`、`yw`、`diw`、`daw`、`ciw`、`caw`、`yiw`、`yaw`。相关的 `b` / `B`、`e` / `E`、`ge` / `gE`、`iW` / `aW` 也使用相同边界；计数、寄存器、撤销、点重复及字符可视选择与之配合。

分词使用运行环境提供的 `Intl.Segmenter('zh', { granularity: 'word' })`，没有引入独立分词库或下载词典。汉字按词处理，非中文部分保留原有 Vim 或 subword 行为。`cw` 保留被修改词之后的空格，`aw` 按词对象规则包含相邻空白。

单次分词采用固定 256 个 UTF-16 单位的窗口，必要时扩展以保留完整代理对，缓存最多 64 项。按实际文本缓存使编辑、撤销及多编辑器复用不会沿用旧偏移；纯英文路径无需初始化分词器。

边界：系统词典可能随平台与运行时版本不同，尚未增加数学专用词典或用户词典。固定窗口边缘可能切开长词；缺少 `Intl.Segmenter` 时降级为完整汉字码点。外部 Neovim 保持自己的词边界。

主要实现：`src/util/chinese-word-boundaries.ts`、`src/vim/chinese-word-range.ts`、`src/vim/chinese-words.ts`。详见 [[chinese-words|中文分词说明]]。

### 4. Markdown Live Preview conceal

新增默认关闭的 Live Preview conceal。自带 Vim 引擎在正常模式与字符可视模式下按可见文本导航，支持首期的单行粗体、斜体、删除线、高亮、行内代码、标题、Markdown 行内链接和带别名的 wikilink。

源码显示有两种策略：停留后延迟展开，或进入编辑时展开。默认延迟 **200 毫秒**，可设置为 **0–10000 毫秒**的整数，`0` 表示立即展开。设置面板、vimrc 和 Lua 均可配置：

```vim
set previewconceal
set previewconcealreveal=delay
set previewconcealdelay=200
```

```lua
vim.opt.previewconceal = true
vim.opt.previewconcealreveal = "delay" -- 或 "insert"
vim.opt.previewconcealdelay = 200
```

停留展开后的区域保持源码，直到光标离开；相邻区域独立处理。编辑时展开当前区域，其他受支持区域继续预览。编辑操作和文本对象保留源码范围，跨格式复制可能包含 Markdown 标记。

解析复用 Obsidian 语法树，按可见行与导航目标建立投影，每个编辑器缓存上限为 256 行、100000 个源码 UTF-16 单位。超过 20000 单位的单行保留原行为。导航本身没有新增等待，计时器仅控制源码展开，并随焦点、模式、移动和销毁取消。

源码模式、Obsidian 内置 Vim、外部 Neovim、表格单元格编辑器、图片、嵌入、数学与生成式 widget 保持原有处理路径。列表、callout、代码块、引用链接及跨行内联格式尚未纳入首期投影；搜索、字符查找及自定义跳转保持源码目标。

主要实现：`src/vim/conceal/`，分别负责模型与映射、行缓存、展开状态、计时器、视图生命周期和 motion 适配。详见 [[preview-conceal|conceal 使用说明]]、[[live-preview-navigation|设计与范围]]。

## 已修复的问题

### 1. 跨应用返回时错误恢复输入法

区域记忆实现期间补齐了两处交接问题：返回同一区域时不应覆盖系统维护的状态；浏览器先发 `focusout`、后发窗口 `blur` 时，仍应保留离开区域的身份。现在按跨应用设置决定是否恢复，不再因该事件顺序误判区域。

对应提交：`aef5463`、`b4b1b0c`；配置开关见 `caa4f6e`。这些属于新区域记忆功能的交接修正。

### 2. 同一编辑器打开另一笔记后输入法不同步

DOM 焦点不变时，原先仅依赖焦点事件的路径不会重新应用新笔记的状态。现在文件变化也会重新协调当前区域，并读取实际 Vim 模式，Normal 笔记可立即使用 Normal 输入法。

对应提交：`f82cc49`。这是区域记忆实现的场景补齐。

### 3. Flash 短拼音搜索先被原生 Vim 处理

拼音模式提交后，原生搜索可能先按字面执行，妨碍 Flash 的预期结果。现在符合条件的 `/`、`?` 短模式由 Flash 提前接管；`:` 命令、替换与其他搜索保留原命令行路径。

对应提交：`7d11890`。这是新增拼音搜索路径的修正。

### 4. 导航提前进入 LaTeX Suite 隐藏源码

自带 Vim 导航原先可能把目标落入 CM6 的原子隐藏区间，在 LaTeX Suite 的展开延迟之前触发源码显示。现于提交光标位置前查询 `EditorView.atomicRanges`，覆盖字符、词、行、显示行、翻页与半页导航；编辑操作保留源码范围，展开后立即读取最新范围。

适配依赖 CM6 的公共范围机制，不修改 LaTeX Suite 的计时器或内部状态。新增 Markdown conceal 也不接管数学区域。这项修复不代表已经建立完整的 MathJax / LaTeX Suite 可见列宽模型；讨论过的数学混合行 `j` 列偏移场景未得到复现，不作为已确认缺陷记录。

对应提交：`f64ce1b`，实现：`src/vim/atomic-range-motions.ts`。属于既有导航与第三方 conceal 的兼容缺口。详见 [[ecosystem-compatibility|插件兼容说明]]。

### 5. 文末数学预览中的 Flash 目标缺失

文末渲染数学块没有尾随换行时，CM6 的 `visibleRanges` 可能省略 MathJax 替换区间，旧扫描因此漏掉目标。现在补扫可视区末尾对应的源码，保留坐标过滤、同 widget 目标去重与 frontmatter 边界。

对应提交：`f64ce1b`，实现：`src/easymotion/targets.ts`。属于既有目标扫描缺陷。

### 6. 已展开的源码一移动就恢复预览

早期 conceal 实现会在下一次移动时重新隐藏源码，导致地址或格式标记无法连续编辑。现在按语法区域保存展开状态，只有实际 Vim 光标离开该区域后才恢复预览。相邻链接、标题内相邻格式分别维护状态；区域边界随文本编辑映射，整段替换后释放旧状态。

状态：已修复，纳入本轮提交。实现：`src/vim/conceal/reveal.ts`、`src/vim/conceal/controller.ts`。属于本轮 conceal 新功能的缺陷。

### 7. 源码展开后闪烁光标仍在旧位置

展开会改变字符布局，但旧逻辑没有及时请求光标重新测量，闪烁光标与动画光标均可能停留在预览时的位置。现在显示变化发出共享布局刷新信号，触发普通 Vim 光标测量，并清除动画光标的几何与字形缓存，无需手动移动。

状态：已修复，纳入本轮提交。实现：`src/vim/cursor-layout.ts`、conceal 控制器及动画光标控制器。刷新不改选区、不制造编辑或撤销记录。属于新展开路径暴露的光标刷新遗漏。

### 8. `gj` 无法进入较短的最后一个显示行

段落在文末换行显示，且最后显示行比当前列短时，底层适配器会同时返回 EOF 边界标记与有效的下一行位置。旧 Vim motion 丢弃所有边界结果，导致 `gj` 原地不动。

现在仅在真实显示行发生变化时接受该边界结果，落到最后一个字符，同时保留期望列；之后 `gk` 可回到原来的列。已在最后显示行时继续 `gj` 仍停止，计数移动也遵循真实边界。

状态：已修复，纳入本轮提交。属于原有 Vim fork 的边界缺陷；关闭新增 conceal 也能复现。核心源码改动保存在 `patches/upstream/codemirror-vim-display-line-eof.diff`，当前通过版本化 `patch-package` 补丁在安装和构建时应用，依赖仍使用 npm registry alias。将来发布包含修复的 fork 版本后应移除临时补丁。证据见 [EOF 回归记录](../../test/specs/display-line-eof-negative-controls.md)。

### 9. Normal 模式的 `I` 插入字母而未进入 Insert

conceal motion 包装器错误地假定调用总是带有完整导航参数和 Vim 状态，而原生 `I` 会直接用 `cm/head` 调用内部 motion，异常中断后按键落入宿主输入。

现在参数不完整的内部调用直接委托原 motion，保留 `I` 的首个非空白字符插入行为。额外审查并验证了同样使用部分参数的 `==`、`gUU`、`g~~`、`g??`，覆盖通用调用契约。

状态：已修复，纳入本轮提交。实现：`src/vim/conceal/motions.ts`。这是新增 conceal 适配引入的回归，与下述搜索缓存问题来源不同。

### 10. 退出查找后再次搜索仍带有旧的 V 选区

`V` 选择文本后按 `Ctrl+F`，首次填入选中文本是预期行为；结束选择后再次打开查找，旧插件仍把历史选区当成当前选区返回。

根因在可视行与宿主命令兼容层：用于异步替换的快照泄漏到 `getSelection()` / `somethingSelected()`。现在查询仅返回当前原生选区或活动 Vim 选区；异步替换使用独立、逐视图、30 秒过期的私有快照，并优先采用新原生选区，消费或销毁后清理。

状态：已修复，纳入本轮提交。实现：`src/vim/visual-line-command-fix.ts`。这是基线中已存在的缺陷，相关缓存可追溯到 2026 年 9 月的 Note Composer / 可视行兼容提交，并非中文分词或新 conceal 引入。修复保留直接调用和宿主命令中的延迟替换能力。证据见 [搜索与异步替换回归记录](../../test/specs/visual-line-search-negative-controls.md)。

### 11. 静态检查误解析安装目录中的构建产物

完整 `npm run verify` 会让 ESLint 尝试按 TypeScript 项目解析安装目录和历史发布目录中的编译版 `main.js`，因这些生成文件不属于源码项目而失败。现在 ESLint 与 Prettier 明确排除 `personal-releases/` 和 `vim-motions-plugin/`，保持历史包内容不变，源码和维护中的文档继续正常检查。

状态：已修复，纳入本轮提交。配置：`eslint.config.mts`、`.prettierignore`。这是生成产物目录纳入个人工作流后暴露的检查范围遗漏。

## 架构与延迟约束

- 输入法由单一管理器串行拥有查询和切换，使用焦点与模式事件，不轮询系统布局。
- Flash 复用首字母映射；中文分词按需初始化、固定窗口处理并限制缓存，不分词整个文档。
- conceal 将源码投影、缓存、区域状态、计时器和 Vim 适配分离，显示与导航共享同一展开状态。
- motion 包装安装顺序为中文分词 → 表格 → Markdown conceal → 原子区间，按相反顺序清理，设置重载后重新捕获当前处理函数。
- `gj` 修正在 Vim 核心路径分发；显示行边界结果才增加必要的坐标检查，普通导航不新增计时器。
- 普通光标与动画光标使用共享布局刷新入口，避免通过合成移动或重写选区修正显示。
